# Prompt 质量实验 · 2026-09-06

## 结论

**更值得继续采用的是明确的 CS/金融采集方向，以及 v3 的选题问题表述；
没有证据支持一口气替换整套采编 prompt。** v3 在预留集的选题盲评分提升
16.25 分，但摘要只提升 2.5 分，未达到事先约定的 +8 分改善门槛。选题仍受
候选换序和生成随机性影响，因此保留为实验候选，不自动进入生产。

这轮不是“越改越好”：v1、v2 都出现新问题，v3 也没有消除全部不稳定性。
最有价值的收获是可复现的评估办法、具体反例和更准确的下一步，而非一个
自称完美的长 prompt。

## 范围与证据

这次实际执行了 **34 次本地、ChatGPT 登录认证的 Codex 调用**，不是 mock：
基线及三个迭代版本的开发集共 20 次，最终版与基线的预留集共 10 次，
两个发现方向的公开搜索对照共 4 次。使用 `gpt-5.6-sol`、锁定的
`openai-codex 0.147.0` 和生产隔离执行器。生产代码基线是
`9c497c4721e144eca59ebe9cc34259d4efeaa9f5`。

- 选题：真实的 30 条候选，正序与倒序各跑一次，不重复搜索。
- 摘要：真实公开证据包，统一两段，比较现有编辑政策与新增写作指令。
  为隔离写作能力，所有版本统一禁止联网，并仅输出正文；没有图卡、独立
  审稿或发布批准。**不是原封不动重跑完整生产作者/审稿流程。**
- 发现：相同真实种子、日期和 150 秒预算，允许公开搜索/open；网页和
  检索结果本身可能变化，不能把所有差异归因于 prompt。
- 输入、实际 prompt、schema、版本/hash、原始输出、验证结果、用量、
  耗时和失败均已保存。未读取私人事件，未写 Notion、未发邮件、未部署。
- 30 次选题/摘要均结构有效；发现对照中 2 次有效、2 次失败。没有登录、
  额度、超时错误；这不代表内容准确率为 100%。

三轮开发比较复用同一组 5 个基线输出，各新版本另生成 5 个输出，不是
每轮把基线重新抽样。预留集双方各新生成 5 个输出。版本变化中仍包含模型
随机性，不能把下面的迭代过程当作已证明每次修改的独立因果效果。

开发集来自一个真实生产运行；预留集来自另一轮独立采集。二者都是
2026-09-06，且相关公开选题此前讨论过，**不是跨日期、完全未见过题材的验证**。
预留集原始输入没有用于调整 prompt，最终版本冻结后才用于对照。摘要预留
样本按固定规则取首个 AI/ML、科学、经济简版的证据，不挑生成得好的输出。

## 什么算“好”

[选题和摘要标准](../README.md) 在第一次比较前确定，后续只补充了操作文档，未
改变其评分维度和权重。发现阶段的 35/35/30 是独立评审使用的探索性诊断，
不当作同等完整预注册的验收门槛。事实、引用、时间基线及执行边界是独立门槛；软指标
按 0–4 锚点评分再加权，不能用漂亮文字抵消重要事实问题。

| 环节 | 主要指标 |
| --- | --- |
| 选题 | 实质进步/重要性 25%，学习机会 20%，证据与新颖度校准 20%，组合取舍 20%，研究可执行性 15% |
| 摘要 | 解释力 30%，证据忠实度 25%，新增理解 20%，阅读收益 15%，时间表述 10% |
| 发现 | 候选价值 35%，可核查性 35%，有效覆盖 30%；成本与结构可用性另列 |

不奖励栏目齐全、来源品牌、链接数、术语数或免责声明长度。“创新敏锐度”
不考能否事后猜中下一个 Transformer，而考能否说清**旧瓶颈、新的办法或
证据、值得观察的下一项验证**。金融不等于行情播报，CS 不等于产品发布。

盲评隐藏版本名字，给评分者同一输入与匿名 A/B，要求引用输出中的具体
片段。评分者是独立助手，不是用户或领域专家；分数不是正确率，也没有
统计显著性。两次候选换序是敏感性检查，不算两个独立新闻日。事实不明与
已证实错误分开记录，关键风险由原始来源复核，不能让模型自己给自己认证。

## 迭代中实际发现了什么

| 版本 | 改动与观察 |
| --- | --- |
| 基线 | 已有事实边界要求，但研究任务常展开成大清单，核心兴趣没有明确作用于稀缺深读位置。 |
| v1 | 改为瓶颈、机制、读者理解目标；AI 解释更自足。设备开票本身是有效行业测量，但其 AI 归因和具体深读收益尚待查明；战报标题仍用“再升级”。 |
| v2 | 增加边际阅读收益、一题少量决定性核查、标题与证据强度一致。油轮标题改善，但 WeatherNext 丢了回看标识；某次选题仅在 note 中承诺简讯，实际任务列表没有选它。 |
| v3 | 明确“任务列表才会被研究/展示”，防止备注假保留；恢复旧研究日期/回看要求，保持简短的机制解释。此后不再根据预留集改 prompt。 |

“再升级”在冻结材料中缺少足够的前后比较支持，应列为过强表述风险；
不能仅凭这次材料缺失，就声称已证明真实局势没有升级。更准确的处理是
把标题缩小到已支持的交战方声明，而非用段落末尾的免责声明补救。

WeatherNext 的 v3 示例：标题明确“回看”，正文解释路径受大尺度气流、强度
受局地过程影响，联合建模为何值得研究；把“超过 24 小时等效提前量”解释
为同等误差下的预测提前量，而不是保证每场灾害提前一天预警。这些是作者方
说明，不能当独立复现或已证实减灾收益。[原始说明](https://deepmind.google/blog/weathernext-ai-model-achieves-breakthrough-in-forecasting-cyclones/)

## 配对评分与稳定性

下表是各轮相对同批基线输出的加权平均差，不是版本的客观排名。
v1/v3 开发集由同一盲评者评分，v2 和预留集另有独立评审；不同评审对同一
基线的绝对评分也不同，所以不能据表声称 v2 必然比 v1 差。

| 比较 | 选题平均分差（2 次换序） | 摘要平均分差（3 个选题） |
| --- | ---: | ---: |
| 开发集 v1 − 基线 | +20.00 | +3.75 |
| 开发集 v2 − 基线 | +7.50 | +9.58 |
| 开发集 v3 − 基线 | +17.50 | +10.00 |
| 预留集 v3 − 基线 | +16.25 | +2.50 |

最终预留集：选题从 70.0 到 86.25，两对均偏好 v3；摘要从 80.0 到 82.5，
一胜两平。开发集的解释改善未以同样幅度出现在预留集，不能只报告开发集的
10 分提升。另将两对开发摘要的 A/B 位置交换，交给另一个独立评审，仍都偏好
v3；这是有限的交叉检查，不是排除位置偏差的统计证明。

选题稳定性仍不足。开发集 v3 正序/倒序入选候选 ID 的交并比为 54.5%，
预留集为 46.2%；预留集前两名所含候选 ID 没有重叠。基线预留集对应为
50.0% 和 33.3%。合并研究任务可以包含多个候选，因此这些是候选 ID 而非
栏目计数；同时改变了顺序并重新采样，无法把差异全部归为位置偏差。

按原来的 +8 分、配对偏好与一致性要求，v3 的选题措辞值得保留，摘要仍属
改善不充分。整体稳定性没有通过足以自动替换默认值的标准。也不能声称
v3 已被证明是所有版本中的全局最优：只有它进入了这批预留验证。

## 发现方向：有实质收益，也有成本代价

独立盲评对原始候选内容评分：技术方向由 58.75 到 75.0，经济/金融方向由
58.75 到 82.5。旧版两次都只重新打开种子来源，没有 search，因此未通过
生产 `parse_discovery` 的搜索要求；**失败结果的可用候选计 0**，但仍保留
内容评分用来诊断原因。这里不是网络或额度故障，也不能把结构失败从样本中删除。

新版各返回 5 个结构有效候选：除重要宏观与产业更新外，补出了密码更新的
安全/自动化权衡、桌面软件更新机制的黑盒安全分析，以及信贷错配的跨境渠道、
准备金与日内结算时点。它们比再加一条同质月报更接近 CS/金融的新增学习机会。
候选仍需后续事实核验，不是已通过审稿的报道。

两个可继续读的原始入口：[USENIX 软件更新研究](https://www.usenix.org/conference/usenixsecurity26/presentation/wan)、
[BIS 支付系统流动性研究](https://www.bis.org/publications/working-paper-1373-settlement-liquidity-colombian-large-value-payment-system-role-reserve-requirements)。

新版两次发现花费 636,464 token，旧版为 296,190；增加约 115%。因此这是
“候选质量/覆盖改善，但搜索成本上升”的结果，不能称为更高效。发现 prompt
与验证器对 search 的要求不够一致，也需要单独修正和重验。

缓存输入已经包含在总输入 1,383,831 中，不重复相加。34 次调用均有完整用量
记录，失败尝试也计入；一次 SDK 调用内部可能多次请求模型。以上不含本段
对话、实现工作和助手盲评的用量，也不换算成固定 Pro 周额度百分比。

新增 28 项 runner 边界测试；全仓 1,762 项测试通过（2 项既有第三方弃用警告），
Ruff、格式、mypy、diff 检查通过。这些只是软件回归检查，不计入内容评分。

本次没有更新本地或线上默认 prompt、提交、推送或部署；`evals/prompts/` 不在服务
扫描路径中。新的本地 runner 及其边界测试用于以后复现实验，测试数量不代表
新闻事实通过率。日期外推、完整实时采编、独立事实审校、邮件渲染与投递不在
这轮摘要对照的结论范围内。

## 下一步最值得做的事

1. 把“简讯是否保留”与“深读优先级”分成明确决策，避免同一个 priority 同时
   承担两个目标。当前实验没有擅自改 DAG、proto 或生产排名器。
2. 让 selection 真正收到已冻结的读者偏好；当前 reader-profile 传给作者，
   但没有传给 shortlist。仅编辑偏好文件不足以改变现有排序目标。
3. 将 CS/金融采集候选作为下一轮输入，约束搜索成本，并明确 search 与
   open 的生产契约；不是靠多开几个相同方向 worker 增加信息量。
4. 把量名、时间基线、比较对象和已有反证保留在材料交接中；测少数关键
   比较能否解释清楚，不继续累加泛泛的“更深入、更客观”形容词。
5. 用其他真实日期、重大事件日和材料稀缺日做新的验证，保留失败和分歧，
   而不是继续调整本次预留集直到得高分。
